# Official upstream port candidates

This is a review queue, **not implementation authorization**. Source references and introduced commits are in the [feature matrix](upstream-feature-matrix.md), pinned by [baseline](baseline.md). MUST_PORT means preserve the relevant correctness behavior in a later independently reviewed fix; it does not mean transplant the upstream function. Official has no checked-in tests.

| Candidate / related matrix behavior | Decision | Reason, compatibility constraints and required evidence |
| --- | --- | --- |
| Ignore foreign SN before heartbeat update | MUST_PORT | Reproduced foreign traffic prolongs C liveness. Add two-host clock tests, then small isolated fix; consider valid-JSON heartbeat definition separately. Specific-topic subscription is useful but not a substitute for a correct handler. |
| Type23 with literal main SN | MUST_PORT | O accepts a legitimate host-statistics form C drops (synthetic probe reproduced). Add host/system/missing/child SN matrix, preserving expansion battery handling/null rules. O `12c2e7c`. |
| Host-only metadata and top-level softver | SHOULD_PORT | Prevent child firmware/model contaminating host and retain firmware in known envelope form. Add child/host/flat/scheduled registry tests; do not change identifiers. O `d0e0c9f`, `sensor.py:1556`. |
| Filter main SN out of child arrays; safe deduplicated aggregation | SHOULD_PORT | Avoid self-child and incomplete get_subdevices. Extend design to C collectors/batteries instead of copying O's plugs+cts-only helper. Characterize entity creation and callback timing first. |
| Periodic child freshness enforcement with availability owned outside value updates | MUST_PORT | C full message fan-out can revive stale cached values. O offers useful separation, but integrate C's cumulative battery policy and HTTP semantics explicitly. Add timer→message→entity tests before behavior change. |
| Coordinator-level plug commMode/no-host guard | SHOULD_PORT | C entity gate already solves the normal UI path. A central boundary prevents future alternate callers bypassing it; add action/notification tests and document whether no-SN changes from silent return to error. |
| Optimistic plug cache update | CONSIDER | Better immediate feedback, but behavior differs from C's telemetry-confirmed plug state; conflicting switchSta/sysSwitch priority must be investigated and publish-failure semantics tested. Do not conflate with mandatory control guard. O `d1f4f68`. |
| Generic CT type2/4 full phase power/total-energy entities | CONSIDER | O exposes more fields for legacy CTs; C type3 already has richer support. Requires recorded payloads, field scaling verification and entity-ID migration plan; do not replace existing subtype power/energy entities. |
| Host-specific MQTT subscriptions | SHOULD_PORT | Reduce unnecessary callbacks and cross-entry coupling. Preserve empty-SN discovery fallback if still supported; test custom prefixes, two entries and unsubscribe/reload. O `12c2e7c`. |
| Generic-message subdevice arrays/points routing | NEEDS_INVESTIGATION | O handles child updates outside 101/102, where C shallow merge can contaminate main state. Collect real payload variants and regression fixtures before changing routing, especially arrays and main fields in same body. |
| Type23 child last-seen refresh | SHOULD_PORT | O timestamps normal child statistics; define whether energy-only refresh should count for power freshness before applying. Keep source/measurement freshness separate. |
| Full-list replacement / immediate unbinding from type101 | NEEDS_INVESTIGATION | O body.devType2/6 replacement loses absent fields/members, conflicting with tested C partial-report preservation. Need authoritative membership/cadence evidence per firmware. Never infer deletion from an empty response alone without that evidence. |
| CT has-power/commState reliability helpers | NEEDS_INVESTIGATION | Fixes empty/offline zero meter fallback, but O also replaces explicit zero with phase sum and accepts nonzero offline data. C's zero and phase-balanced regressions must remain protected. Port a validated rule, not the entire energy algorithm. |
| Official battery preference and home export branches | DO_NOT_PORT | Would replace tested whole-stack energy balance with main-unit bat fields and reintroduce negative-home example. C already solves the intended display differently with tests and attributed hardware evidence. |
| otherLoadPw home fallback | NEEDS_INVESTIGATION | C exposes raw otherLoadPw; O substitutes it when calculated home is zero. That changes physical meaning/source priority and could override valid zero. Require captures and meter comparisons. |
| calc_ac_socket_power and calc_battery_* intermediate keys | DO_NOT_PORT | O calculates them but no entity consumes these particular keys. C already exposes EPS input/signed output and raw/total battery values. No demonstrated missing user capability. |
| average_soc and read-only work_mode entities | DO_NOT_PORT | C bms_soc and work-mode select represent the same raw fields. New duplicate IDs would fragment history; soc's average-vs-BMS label needs evidence before any later rename. |
| Host-prefixed child IDs / dual main registry identifiers | DO_NOT_PORT | Breaks C's established IDs; O main_ controls are explicitly deleted by C migration. Same-child-SN multi-host isolation remains a real future migration design question, not a direct port. |
| Expanded deviceType labels 1/2/4 and serial_number metadata | CONSIDER | Labels alone do not imply host support; child guard must precede adoption. Serial_number is user-identifying and needs diagnostics redaction. Preserve existing model display until known message scope confirmed. |
| entry.async_start_reauth and missing-entry guard | CONSIDER | C already has functional trigger/form code; O uses a different HA lifecycle API. Add completed flow, removal/unload and repeat-trigger tests before API cleanup. |
| async_step_import | CONSIDER | Explicit Official-only method, but no YAML schema/setup initiator found. Do not claim YAML support just by adding it; only implement if an actual supported import use case is established. |
| Independent error handling for each subdevice poll | SHOULD_PORT | O continues category6 after category2 failure; C outer loop try skips remainder. Add publish-failure sequencing tests; preserve C category3 and cadence. |
| Five-second cadence and every-cycle 105 | DO_NOT_PORT | Intentional C traffic reduction; no evidence for reverting and risks stale snapshot overwrites. Keep C exact batch/sleep timing during extraction. |
| zh-Hans translation | CONSIDER | Useful language coverage but Official entity schema/names differ; adapt to C translation keys and completeness check, do not copy file blindly. |
| Per-message INFO logging | DO_NOT_PORT | No missing functionality; increases noise and exposes serial/topic values. Keep protocol detail at DEBUG with redaction. |

No candidate adds provisioning, pairing, virtual meters, RPC emulation or unverified commands. After structural extraction, re-evaluate candidates against the then-current upstream SHA and record selected behavior, local PR, tests and migration consequences in a future `docs/upstream-sync.md`.

The Official first-category2 type101 probe also raises a caught missing-plugs KeyError before discovery. Any investigation of full-list semantics must cover empty-cache message ordering; Official source is a protocol reference, not proof that every implementation path is safe.
